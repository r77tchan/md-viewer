## KAGAYOI Engineering

### 構成と設定

- 2026-10-06 に試用し、終了時にこの Mac からすべて削除した（CLI、`~/.config/kagayoi/`、`~/.local/state/kagayoi/`、Docker のイメージ・ボリューム・ネットワーク）。また使うならインストールからやり直す。
- 当時の構成：CLI は `~/.local/bin/kagayoi`（0.9.0）。設定は `~/.config/kagayoi/` にあり、`credentials.json` に GitHub と Claude Code のトークン、`config.json` に Agent・認証方式・Worker 数が入る。Claude Code / subscription / Worker 2 で、Host は `kagayoi start -d` で裏で動かし、ログは `~/.local/state/kagayoi/host.log` だった。
- `kagayoi config` は対話式でしか設定できず、Claude の Bash からは操作できない。ユーザーに自分のターミナルで実行してもらう。
- Claude Code のトークンは `claude setup-token` で発行する。トークンはチャットに貼らせず、別のターミナルで扱ってもらう。
- AI はこの Mac の Docker コンテナの中で動く（Issue ごとに `kagayoi_r77tchan_md-viewer_<番号>`）。外への通信は proxy コンテナを通り、許可された宛先にしか出られない。ブランチは `kagayoi/issue-<番号>`。

### AI に渡る指示と設定

- `.kagayoi/instructions/*.md` は、Host が main（デフォルトブランチ）から読む。
- CLAUDE.md・`doc/指示.md`・`.claude/settings.json` は、コンテナで作業を始めたブランチの版が使われる。新しい Issue は main から、差し戻し（rework）は PR のブランチから始まるので、main の変更は差し戻し中の Issue には効かない。
- コンテナの Claude Code は Docker イメージに入っている版（2.1.283）で、手元のユーザー設定（`~/.claude/settings.json`）は渡らない。指定がないと既定の `claude-sonnet-5`・effort high で動く。
- モデルは `.claude/settings.json` の `model`（正式な ID で書く）と `effortLevel` で指定する。今は `claude-sonnet-5-5`・high。手元は `.claude/settings.local.json`（Git 管理外）で Opus・xhigh に上書きしている。
- `claude-sonnet-5-5` を指定すると、Host のログに `[claude-code:unrecognized_model]` が出る。古い Claude Code が知らないモデル名だと警告しているだけで、作業記録を見ると実際に `claude-sonnet-5-5` が使われている（#9 で確認）。
- コンテナの Claude Code の版は、kagayoi の Docker イメージ（`kagayoi-agent:<kagayoi の版>`）に固定されている。上げるには kagayoi の更新（`kagayoi update` → `kagayoi stop` → `kagayoi start -d`）を待つ。キャッシュ用ボリューム（`/cache`、PATH で優先される）に新しい版を入れる手もあるが、kagayoi が出力形式に依存しているので使わない。
- 実際に使われたモデルは、作業中または停止中のコンテナから `docker cp <コンテナ>:/root/.claude/projects <保存先>` で作業記録をコピーし、各行の `message.model` を見ると分かる。
- AI は古い知識で版を書くことがあった（HeroUI をベータ版、Node を 20 系とした）。`design.md` に「版は `npm view` で最新を確認する」を足してからは守られている。

### Board での進め方

- Issue には `kagayoi:design:human` と `kagayoi:review:human` を付け、設計の後とマージの前に必ず人が確認するようにしている。
- 差し戻しのコメントも承認のコメントも Issue のコメントとして投稿され、次のフェーズの AI がそれを読んで従う。細かい修正は、差し戻さずに承認時のコメントで伝えられる。
- 「失敗・差し戻しが3回目で人に委ねる」仕組みがある（Issue 画面に「失敗 x / 3」と出る）。設計の差し戻しがこの回数に入るかは未確認。
- 衝突している PR で「受け入れてマージ」を押すと、マージされずに自動で Implement に戻り、AI が `git merge origin/HEAD` で衝突を解消する。
- 衝突が確実なときは、受け入れずにコメント付きで差し戻すと、衝突の解消と追加の修正を1回で頼める（#4 で、lowlight を直接の依存にすることと、package-lock.json を npm install で作り直すことが反映された）。
- 衝突を解消するときに main を取り込むので、その後の Review では main の `.claude/settings.json` などが使われる。
- Implement の push から Review の開始まで、1〜5分ほど空くことがある。止まったように見えたら、`docker top kagayoi_r77tchan_md-viewer_<番号>` で `claude` などのプロセスが動いているかを見る。
- GitHub の画面では「マージできる」と出ていても、GitHub からはマージしない。判断は Board で行う。
- Implement と Review は別のコンテナ・別の会話で動く。設計の後はコンテナを残して再開に使い、push やレビューが終わると片付けられる。
- Issue の前後関係を kagayoi が自動で守るかは未確認。前提の Issue がマージされてから「担当する」を押す。
- PR も Issue と同じ番号の列を使うので、次の Issue の番号は予想できない（#6〜#8 は PR）。
- 2026-10-06 は、#1 を単独 → #2・#3 を並列 → #9 を単独 → #4・#5 を並列 → #13（狭い画面のヘッダー）、の順に進めた。

### 規約上の注意（2026-10-06 に調べた結果）

- Anthropic の公式ページでは、利用者が改変されていない Claude Code 本体に自分のサブスクでサインインすることは認められている（他社の基盤が Claude Code を動かす場合も含む）。今回の使い方（自分の Mac・自分のリポジトリ・自分1人）は、これに当たると判断した。
- 一方で、他社の開発者がサブスクのログインを提供すること、認証情報を保存・仲介することは認められていない。kagayoi の subscription 方式（`claude setup-token` のトークンを貼り付けて保存させる作り）は、運営側の問題としてグレー。
- 根拠：https://code.claude.com/docs/en/legal-and-compliance#authentication-and-credential-use
- また使うなら api-key 方式にする。サブスクのトークンは他人と共有しない。チームで1台の Host を共有するなら、Claude も OpenAI も API キーが前提になる。

## 開発メモ

- 手元で PR を確認するときは、`gh pr checkout <PR番号>` → `npm ci` → `npm run dev` で、http://localhost:5173/md-viewer/ を開く。終わったら `git switch main` に戻る。確認用のサンプルは `samples/sample.md` と `samples/toc.md`。
- HeroUI v3 の `.typography-prose` は、見出しと段落に余白を付けない（Tailwind の初期化 CSS で 0 になる）。余白は `src/styles/globals.css` で補っている。
- テーマは HeroUI の `useTheme`（localStorage のキーは `heroui-theme`）。`index.html` のインラインスクリプトで、初回表示のちらつきを防いでいる。
- `rehype-highlight` は言語を絞っても lowlight の全37言語を読み込むので、Vite の alias で `lowlight` を `src/lib/lowlightWithoutCommon.ts` に差し替えている。そのため `lowlight` を直接の依存にして、`node_modules` の直下に置いている。
- ビルドすると JS が 500kB を超え、Vite の警告が出る（2026-10-06 時点で 536kB、gzip 166kB）。

## 作業環境

- Bash ツールのシェルは zsh。配列の添字が1から始まるので、`${arr[0]}` は空になる。
- zsh では、改行を含む変数を引用符なしで渡しても単語に分かれない（`kill $pids` が失敗した）。
- `lsof -ti tcp:<ポート>` は、つながっているブラウザのプロセスも返す。止めるときは `-sTCP:LISTEN` で、待ち受けているプロセスだけに絞る。
