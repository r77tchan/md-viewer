- 意味のある変更のまとまりごとに git でコミットする。コミットメッセージには変更の意図を書く。
- 終える前にテストを通す。要件に実際の動作確認が含まれる場合は、コンテナ内でアプリを起動して確認する。
- 終わったら、やったことを簡潔に報告する。
- 設計案、報告、PR の本文、コミットメッセージ、レビューコメントは日本語で書く。
- doc/指示.md の「勝手に進まないこと。ユーザーに進めて良いか確認すること」は対話セッション向けのルール。KAGAYOI では人の確認は Board での承認（Design / Review）で行うので、フェーズ内の作業は確認を求めずに進める。要件が分からず進められないときだけ質問する。
